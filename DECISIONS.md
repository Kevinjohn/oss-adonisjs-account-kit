# Decisions

## Departures

1. **Aligning** — PKG-7. First-party `@kevinjohn/*` peers are pinned to the exact supported release until launch, because the packages depend on one specific Account Kit version. Third-party peers use caret ranges. Brought into line by #1036.

2. **Aligning ([conventions #24](https://github.com/Kevinjohn/oss-adonisjs-code-conventions/issues/24))** — IMP-5, NAM-3 and PKG-6. Setup generators, consumer renderers, demo overlays and setup fixtures contain application source strings. Those strings correctly use application aliases and optional application integrations; each rendered module has its own class. They are not executable package imports or class declarations. In particular, Ally is imported by the generated application configuration, not by the package. The checker currently scans the strings as package source. Keep the generated application contracts until syntax-aware checking distinguishes these contexts; links name only the affected files.
3. **Aligning ([conventions #25](https://github.com/Kevinjohn/oss-adonisjs-code-conventions/issues/25))** — PKG-1. The repository's required layout places public exported subpath entry points in `auth/main.ts`, `http/main.ts` and `transaction/main.ts`; these only re-export implementation in `src/`. VitePress configuration and theme source under `docs/.vitepress` belong to the documentation site, not the shipped package. The layout checker does not distinguish entry points and documentation tooling from implementation. Preserve the repository layout while that distinction is brought into line.
4. **Aligning ([conventions #26](https://github.com/Kevinjohn/oss-adonisjs-code-conventions/issues/26))** — IMP-5. The workflow's pre-install classifier must remain plain JavaScript (`bin/classify_changed.mjs`), as the repository's script rule requires. Its callers import the actual `.mjs` source. The VitePress theme imports the actual `.vue` single-file component. These prescribed extensions cannot become `.ts` without changing their execution contracts; the checker must recognise their source kinds.
5. PKG-23. `src/setup/generated_env_helpers.ts` and `src/setup/session_config.ts` emit environment reads into the application's configuration files. Neither reads the package's process environment. Moving these reads out of their generated config destination would break application configuration ownership. The checker scans source strings as executable code; [conventions #24](https://github.com/Kevinjohn/oss-adonisjs-code-conventions/issues/24) tracks that limitation.
