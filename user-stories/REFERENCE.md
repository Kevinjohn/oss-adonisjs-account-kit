# Reference

## Actors and boundaries

- **Account holder**: a person registering, authenticating, recovering credentials, changing settings, using invitations, or requesting account data actions. Account Kit does not supply a frontend.
- **Application**: owns user model, route mounting or controllers, validation and response design, signup eligibility, invitation authorisation, profile fields, notification delivery, application language, account-domain data and authorisation callbacks. There is no universal application role built into Account Kit.
- **Application operator**: installs/configures providers, migrations, session/auth/limiter/mail integration, enables optional capabilities, schedules pruning and uses Ace commands. Shell-only operator services are not an HTTP authorisation boundary.
- **Social provider**: configured Ally integration (currently Google/GitHub recipes) that returns provider identity to the application flow.

## Managed request and response boundary

[`registerManagedRoutes`](../src/http/managed.ts) mounts one named handler per selected endpoint. On request, [`executeManagedRequest`](../src/http/managed_execution.ts) applies proof headers, enforces the Shield prerequisite on session writes and the session CSRF endpoint, resolves `kit()`, checks guard support and charges the proof-route budget where applicable. The shared wrapper reads the guard credential for limited and active endpoints. Active endpoints call `requireActive` unless `verificationRequired: false` selects `current`. Public endpoints skip this shared check. Their own handlers can still require a current account, as in [social identity linking](US-ACCOUNT-21-link-social-identity.md) and [provider reauthentication](US-ACCOUNT-23-prove-social-action.md).

[Managed session logout](US-ACCOUNT-04-sign-out.md) can terminate a stale session and return 204 when the guard supplies credential evidence and the subsequent account check raises `E_ACCOUNT_KIT_INVALID_SESSION`. A refusal from the guard itself propagates before that recovery branch. For endpoint-specific checks and results, find the relevant story in [PATHS](PATHS.md#managed-http-paths).

The [managed HTTP guide](../docs/guide/managed-http.md#inspection-never-consumes-proof) documents proof headers, retries and the 202 `{ committed: true }` acknowledgement when a full committed result is unavailable. The [error reference](../docs/reference/errors.md) documents public codes. [Public identity mapping](../src/error_identity.ts) masks invalid sessions as `E_INVALID_CREDENTIALS`, invitation management denial as invitation not found, authorisation denial as forbidden, and server failures as operation failed. Invalid-token codes depend on the proof kind. Exception exports and public codes can differ: for example, the registration duplicate-email exception uses `E_ACCOUNT_KIT_EMAIL_ALREADY_REGISTERED`. [Managed response mapping](../src/http/responses.ts) negotiates JSON or JSON:API and preserves throttle headers. The route wrapper logs mapped server errors and passes unmapped errors to the application. Endpoints with their own acknowledgement or recovery path describe it in their story.

## Managed password fields

The default managed JSON validators require confirmation fields alongside the service inputs: password change uses `newPasswordConfirmation` equal to `newPassword`; reset, activation and invitation acceptance use `passwordConfirmation` equal to `password`. These fields belong to the HTTP schemas, not the corresponding service method signatures. Managed signup (US-ACCOUNT-02) uses `passwordConfirmation` equal to `password` in its default validator. Invitation acceptance and signup may replace their validators through managed extensions. The `registration.register` service does not take a confirmation argument.

`Current` means source exposes a journey when enabled/configured; it is not a runtime test result. Capabilities such as magic link, session management, account data, social auth, admission, OpenAPI, and managed routes require explicit setup. The catalogue uses the six availability definitions and maintenance rules in the portable [TEMPLATE](TEMPLATE.md).

The [managed HTTP paths](PATHS.md) identify the story for every route. [US-ACCOUNT-63](US-ACCOUNT-63-share-transaction-helpers.md) covers the public transaction subpath shared with consuming packages.
