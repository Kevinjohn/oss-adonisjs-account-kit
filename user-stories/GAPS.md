# Retained boundaries and decision gaps

Source and product guides were reconciled for the catalogue baseline. These documented boundaries have current contracts; they are not missing package work. No unresolved product-target mismatch was identified in this documentation scope. Public authentication enforcement, host-policy ownership and shell-trusted admission operations are included in the source reconciliation.

| Boundary                                                                                                            | Existing contract                                                                                                                                                                                                              | Story treatment                                                                                                                                                          |
| ------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Authentication reads validate the current guard credential; host-owned access decisions remain outside Account Kit. | [authentication.current](../src/authentication.ts), [inspectAccountAccess](../src/account_access_inspection.ts) and [withCurrent](../src/authentication.ts) define credential enforcement and callback transaction boundaries. | US-ACCOUNT-39 through US-ACCOUNT-43 describe safe current-account reads, active checks, current-sign-in writes, authorized snapshots and host-owned restriction changes. |
| The host owns user model, frontend, route mounting, signup policy and application authorization.                    | The [feature guide](../docs/guide/features.md) distinguishes service APIs from optional managed JSON routes; [managed HTTP](../docs/guide/managed-http.md) documents guard and route ownership.                                | Stories name the service or optional entry and do not imply package-supplied screens or universal roles.                                                                 |
| Social authentication depends on host provider setup and trusted policy.                                            | [Social authentication](../docs/guide/social-authentication.md) defines state/PKCE, linked, link_required and new outcomes, registration continuation and recent proof.                                                        | US-ACCOUNT-20 through US-ACCOUNT-23 and US-ACCOUNT-53 separate sign-in, linking, unlinking, proof and confirmed identity reads.                                          |
| Admission has no roles, admin pages or managed admission routes.                                                    | [Admission guide](../docs/guide/admission.md) assigns approval authority to host callbacks and requires host-owned route gating.                                                                                               | US-ACCOUNT-24 through US-ACCOUNT-28 distinguish user request, route gate, decision, revocation and installation.                                                         |
| Shell admission operations trust application operators with shell access and bypass actor callbacks.                | [AccountAdmission.operator](../src/admission/service.ts) and its command loader define bootstrap/cancel, invitation-evidence grant, approve and revoke behavior.                                                               | US-ACCOUNT-46 through US-ACCOUNT-50 separate those operations and identify shell access as their authority boundary.                                                     |
| Invitation evidence and admission cleanup require host lifecycle wrappers.                                          | [withInvitationEvidence](../src/admission/invitation_evidence.ts) and [withAdmissionCleanup](../src/admission/cleanup.ts) run inside invitation/deletion transactions.                                                         | US-ACCOUNT-51 records the opt-in integration hooks and transaction contract.                                                                                             |
| Host application data retention/export/deletion obligations remain with the application.                            | [Account data guide](../docs/guide/account-data.md) defines exported package data and transactional host callbacks.                                                                                                            | US-ACCOUNT-18 and US-ACCOUNT-19 separate export and deletion and identify the host callback boundary.                                                                    |
| Adapter and notification transports are configured by the host.                                                     | [Adapters](../docs/guide/adapters.md) and [notifications](../docs/guide/notifications.md) document supported integration contracts and their limits.                                                                           | US-ACCOUNT-34 and US-ACCOUNT-35 describe adapter selection and delivery integration without asserting every runtime combination was exercised.                           |

No implementation target is invented where the repository has none.
